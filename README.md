## Алхам 2: Чанарын сценариуд (6 хэсэгтэй формат)

### Сценарио 1: Performance (`/cart/add`)

| Хэсэг | Агуулга |
|-------|---------|
| **Тойм** | Хэрэглэгч бараа сагсанд нэмэхэд систем шууд хариу өгнө |
| **Системийн төлөв** | Сервер хэвийн ажиллаж байна, халаалт дууссан |
| **Орчны төлөв** | Хэвийн ачаалал: 20 зэрэгцээ хэрэглэгч (VU), нийт ~45 хүсэлт/с, үүнээс `/cart/add` руу ~15 хүсэлт/с, 1 минут тогтмол |
| **Гадаад өдөөлт** | Хэрэглэгч `POST /cart/add` хүсэлт илгээнэ |
| **Шаардлагатай хариу** | Сервер `200 OK` болон `{ ok: true }` буцаана |
| **Хэмжүүр** | Хүсэлтийн 95% нь **10 ms**-ээс, 99% нь **25 ms**-ээс бага хугацаанд хариу авна |

### Сценарио 2: Reliability (`/pay`)

| Хэсэг | Агуулга |
|-------|---------|
| **Тойм** | Хэрэглэгч төлбөр төлөхөд үйлдэл амжилттай болно |
| **Системийн төлөв** | Сервер хэвийн ажиллаж байна. Төлбөрийн гарц (gateway) хааяа timeout өгдөг (~5%) |
| **Орчны төлөв** | Хэвийн ачаалал: 20 VU, `/pay` руу ~15 хүсэлт/с, 1 минут |
| **Гадаад өдөөлт** | Хэвийн хэрэглэгчийн `POST /pay` төлбөрийн үйлдэл |
| **Шаардлагатай хариу** | Сервер `200 OK` болон `{ paid: true }` буцаана. Gateway алдаа гарвал `500` болон алдааны мессеж буцааж, сервер өөрөө унахгүй |
| **Хэмжүүр** | Төлбөрийн хүсэлт эвдрэх магадлал (POFOD) **< 0.08**, өөрөөр хэлбэл 1 минутын цонхонд error rate 8%-иас бага |

### Сценарио 3: Availability (сервер унаж дахин асах)

| Хэсэг | Агуулга |
|-------|---------|
| **Тойм** | Сервер гэнэт унасны дараа үйлчилгээ богино хугацаанд сэргэнэ |
| **Системийн төлөв** | Сервер хэвийн ажиллаж, бүх endpoint хариу өгч байна |
| **Орчны төлөв** | 20 VU тасралтгүй хүсэлт илгээж байгаа (cart, report, pay), 2 минутын цонх |
| **Гадаад өдөөлт** | **Эвдрэл (crash):** серверийн процесс гэнэт зогсоно (Ctrl+C) |
| **Шаардлагатай хариу** | Зогсолтын үеийн хүсэлтүүд хурдан алдаа (connection refused) авна, удаан гацахгүй. Процесс дахин асмагц бүх endpoint гар оролцоогүйгээр хэвийн хариу өгнө |
| **Хэмжүүр** | 2 минутын цонхонд нийт хүсэлтийн **≥ 90%** нь амжилттай (availability ≥ 90%). **Сэргэх хугацаа ≤ 10 секунд** (унаснаас дахин хариу өгөх хүртэл) |

### Сценарио 4 (нэмэлт): Performance (`/report`)

| Хэсэг | Агуулга |
|-------|---------|
| **Тойм** | Хэрэглэгч тайлан нээхэд хүлээж болохуйц хугацаанд гарна |
| **Системийн төлөв** | Сервер хэвийн. Тайлан бэлдэхэд 200–400 ms зарцуулдаг |
| **Орчны төлөв** | 20 VU, `/report` руу ~15 хүсэлт/с, 1 минут |
| **Гадаад өдөөлт** | `GET /report` хүсэлт |
| **Шаардлагатай хариу** | `200 OK`, `{ rows: 20000 }` |
| **Хэмжүүр** | Хүсэлтийн 95% нь **450 ms**-ээс бага хугацаанд хариу авна |

**"Сайн сценариогийн 5 шинж"-ээр шалгавал:** *итгэмжтэй* (тоо бодит хэмжилтээс гарсан), *үнэ цэнэтэй* (сагс, төлбөр, сэргэлт бол хэрэглэгч шууд мэдрэх үйлдлүүд), *тодорхой* (endpoint, ачаалал, цонх заасан), *нарийн* (p95/p99, POFOD, % гэсэн тоон хэмжүүр), *ойлгомжтой* (нэг сценарио нэг чанарын шинжийг хэмждэг).
